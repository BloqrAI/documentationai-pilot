## Installation Issues

### Package not found on JSR

<strong>Error:</strong>

```
error: JSR package not found: @bloqr/compiler
```

<strong>Solution:</strong>
Use npm import as fallback:

```typescript
import { compile } from 'npm:@bloqr/compiler';
```

Or install via npm:

```bash
npm install @bloqr/compiler
```

### Deno version incompatibility

<strong>Error:</strong>

```
error: Unsupported Deno version
```

<strong>Solution:</strong>
Bloqr Compiler requires Deno 2.0 or higher:

```bash
deno upgrade
deno --version  # Should be 2.0.0 or higher
```

### Permission denied errors

<strong>Error:</strong>

```
error: Requires net access to "example.com"
```

<strong>Solution:</strong>
Grant necessary permissions:

```bash
# Allow all network access
deno run --allow-net your-script.ts

# Allow specific hosts
deno run --allow-net=example.com,github.com your-script.ts

# For file access
deno run --allow-read --allow-net your-script.ts
```

## Compilation Errors

### Invalid configuration

<strong>Error:</strong>

```
ValidationError: Invalid configuration: sources is required
```

<strong>Solution:</strong>
Ensure your configuration has required fields:

```typescript
const config: IConfiguration = {
    name: 'My Filter List', // REQUIRED
    sources: [ // REQUIRED
        {
            name: 'Source 1',
            source: 'https://example.com/list.txt',
        },
    ],
    // Optional fields...
};
```

### Source fetch failures

<strong>Error:</strong>

```
Error fetching source: 404 Not Found
```

<strong>Solutions:</strong>

1. <strong>Check URL validity:</strong>

```typescript
// Verify the URL is accessible
const response = await fetch(sourceUrl);
console.log(response.status); // Should be 200
```

2. <strong>Handle 404s gracefully:</strong>

```typescript
// Use exclusions_sources to skip broken sources
const config = {
    name: 'My List',
    sources: [
        { name: 'Good', source: 'https://good.com/list.txt' },
        { name: 'Broken', source: 'https://broken.com/404.txt' },
    ],
    exclusions_sources: ['https://broken.com/404.txt'],
};
```

3. <strong>Check circuit breaker:</strong>

```
Source temporarily disabled due to repeated failures
```

Wait 5 minutes for circuit breaker to reset, or check the source availability.

### Transformation errors

<strong>Error:</strong>

```
TransformationError: Invalid rule at line 42
```

<strong>Solution:</strong>
Enable validation transformation to see detailed errors:

```typescript
const config = {
  name: "My List",
  sources: [...],
  transformations: [
    "Validate",  // Add this to see validation details
    "RemoveComments",
    "Deduplicate"
  ]
};
```

### Memory issues

<strong>Error:</strong>

```
JavaScript heap out of memory
```

<strong>Solutions:</strong>

1. <strong>Increase memory limit (Node.js):</strong>

```bash
node --max-old-space-size=4096 your-script.js
```

2. <strong>Use streaming for large files:</strong>

```typescript
// Process sources in chunks
const config = {
    sources: smallBatch, // Process 10-20 sources at a time
    transformations: ['Compress', 'Deduplicate'],
};
```

3. <strong>Enable compression:</strong>

```typescript
transformations: ['Compress']; // Reduces memory usage
```

## Performance Issues

### Slow compilation

<strong>Symptoms:</strong>

- Compilation takes >60 seconds
- High CPU usage
- Unresponsive UI

<strong>Solutions:</strong>

1. <strong>Enable caching (API/Worker):</strong>

```typescript
// Cloudflare Worker automatically caches
// Check cache headers:
X-Cache-Status: HIT
```

2. <strong>Use batch API for multiple lists:</strong>

```typescript
// Compile in parallel
POST /compile/batch
{
  "requests": [
    { "id": "list1", "configuration": {...} },
    { "id": "list2", "configuration": {...} }
  ]
}
```

3. <strong>Optimize transformations:</strong>

```typescript
// Minimal transformations for speed
transformations: [
    'RemoveComments',
    'Deduplicate',
    'RemoveEmptyLines',
];

// Remove expensive transformations like:
// - Validate (checks every rule)
// - ConvertToAscii (processes every character)
```

4. <strong>Check source count:</strong>

```typescript
// Limit to 20-30 sources max
// Too many sources = slow compilation
console.log(config.sources.length);
```

### High memory usage

<strong>Solution:</strong>

```typescript
// Use Compress transformation
transformations: ['Compress', 'Deduplicate'];

// This reduces memory usage by 70-80%
```

### Request deduplication not working

<strong>Issue:</strong>
Multiple identical requests all compile instead of using cached result.

<strong>Solution:</strong>
Ensure requests are identical:

```typescript
// These are DIFFERENT requests (different order)
const req1 = { sources: [a, b] };
const req2 = { sources: [b, a] };

// These are IDENTICAL (will be deduplicated)
const req1 = { sources: [a, b] };
const req2 = { sources: [a, b] };
```

Check for deduplication:

```
X-Request-Deduplication: HIT
```

## Network & API Issues

### Rate limiting

<strong>Error:</strong>

```
429 Too Many Requests
Retry-After: 60
```

<strong>Solution:</strong>
Respect rate limits:

```typescript
const retryAfter = response.headers.get('Retry-After');
await new Promise((resolve) => setTimeout(resolve, retryAfter * 1000));
```

Rate limits:

- **Per IP**: 60 requests/minute
- **Per endpoint**: 100 requests/minute

### CORS errors

<strong>Error:</strong>

```
Access to fetch at 'https://...' from origin 'https://...' has been blocked by CORS
```

<strong>Solution:</strong>
Use the API endpoint which has CORS enabled:

```typescript
// ✅ CORRECT - CORS enabled
fetch('https://api.bloqr.dev/compile', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ configuration }),
});

// ❌ WRONG - Direct source fetch (no CORS)
fetch('https://random-site.com/list.txt');
```

### Timeout errors

<strong>Error:</strong>

```
TimeoutError: Request timed out after 30000ms
```

<strong>Solution:</strong>

1. <strong>Check source availability:</strong>

```bash
curl -I https://source-url.com/list.txt
```

2. <strong>Circuit breaker will retry:</strong>

- Automatic retry with exponential backoff
- Up to 3 attempts
- Then source is temporarily disabled

3. <strong>Use fallback sources:</strong>

```typescript
sources: [
    { name: 'Primary', source: 'https://primary.com/list.txt' },
    { name: 'Mirror', source: 'https://mirror.com/list.txt' }, // Fallback
];
```

### SSL/TLS errors

<strong>Error:</strong>

```
error: Invalid certificate
```

<strong>Solution:</strong>

```bash
# Deno - use --unsafely-ignore-certificate-errors (not recommended)
deno run --unsafely-ignore-certificate-errors script.ts

# Better: Fix the source's SSL certificate
# Or use HTTP if available (less secure)
```

## Cache Issues

### Stale cache

<strong>Issue:</strong>
API returns old/outdated results.

<strong>Solution:</strong>

1. <strong>Check cache age:</strong>

```typescript
const response = await fetch('/compile', {...});
console.log(response.headers.get('X-Cache-Age'));  // Seconds
```

2. <strong>Force cache refresh:</strong>
   Add a unique parameter:

```typescript
const config = {
  name: "My List",
  version: new Date().toISOString(),  // Forces new cache key
  sources: [...]
};
```

3. <strong>Cache TTL:</strong>

- Default: 1 hour
- Max: 24 hours

### Cache miss rate high

<strong>Issue:</strong>

```
X-Cache-Status: MISS
```

Most requests miss cache.

<strong>Solution:</strong>
Use consistent configuration:

```typescript
// BAD - timestamp changes every time
const config = {
  name: "My List",
  version: Date.now().toString(),  // Always different!
  sources: [...]
};

// GOOD - stable configuration
const config = {
  name: "My List",
  version: "1.0.0",  // Static version
  sources: [...]
};
```

### Compressed cache errors

<strong>Error:</strong>

```
DecompressionError: Invalid compressed data
```

<strong>Solution:</strong>
Clear cache and recompile:

```typescript
// Cache will be automatically rebuilt
// If persistent, file a GitHub issue
```

## Deployment Issues

### `deno: not found` error during deployment

<strong>Error:</strong>

```
Executing user deploy command: deno deploy
/bin/sh: 1: deno: not found
Failed: error occurred while running deploy command
```

<strong>Cause:</strong>
This error occurs when Cloudflare Pages is configured with `deno deploy` as the deploy command. This project uses Cloudflare Workers (not Deno Deploy) and should use `wrangler deploy` instead.

<strong>Solution:</strong>
Update your Cloudflare Pages dashboard configuration:

1. Go to your Pages project settings
2. Navigate to "Builds & deployments"
3. Under "Build configuration":

   - Set **Build command** to: `npm install`
   - Set **Deploy command** to: (leave empty)
   - Set **Build output directory** to: `public`
   - Set **Root directory** to: (leave empty)
4. Save changes and redeploy

For detailed instructions, see the [Cloudflare Pages Deployment Guide](/deployment/cloudflare-pages).

<strong>Why this happens:</strong>

- This is a Deno-based project, but it deploys to **Cloudflare Workers**, not Deno Deploy
- The build environment has Node.js/pnpm but not Deno installed
- Wrangler handles the deployment automatically

### Cloudflare Worker deployment fails

<strong>Error:</strong>

```
Error: Worker exceeded memory limit
```

<strong>Solutions:</strong>

1. <strong>Check bundle size:</strong>

```bash
du -h dist/worker.js
# Should be < 1MB
```

2. <strong>Minify code:</strong>

```bash
deno bundle --minify src/worker.ts dist/worker.js
```

3. <strong>Remove unused imports:</strong>

```typescript
// BAD
import * as everything from '@bloqr/compiler';

// GOOD
import { compile, FilterCompiler } from '@bloqr/compiler';
```

### Worker KV errors

<strong>Error:</strong>

```
KV namespace not found
```

<strong>Solution:</strong>
Ensure KV namespace is bound in wrangler.toml:

```toml
[[kv_namespaces]]
binding = "CACHE"
id = "your-kv-namespace-id"
```

Create namespace:

```bash
wrangler kv:namespace create CACHE
```

### Environment variables not set

<strong>Error:</strong>

```
ReferenceError: CACHE is not defined
```

<strong>Solution:</strong>
Add bindings in wrangler.toml:

```toml
[env.production]
vars = { ENVIRONMENT = "production" }

[[env.production.kv_namespaces]]
binding = "CACHE"
id = "production-kv-id"
```

## Platform-Specific Issues

### Deno issues

**Issue: Import map not working**

<strong>Solution:</strong>

```bash
# Use deno.json, not import_map.json
# Ensure deno.json is in project root
```

**Issue: Type errors**

<strong>Solution:</strong>

```bash
# Clear Deno cache
rm -rf ~/.cache/deno
deno cache --reload src/main.ts
```

### Node.js issues

**Issue: ES modules not supported**

<strong>Solution:</strong>
Add to package.json:

```json
{
    "type": "module"
}
```

Or use .mjs extension:

```bash
mv index.js index.mjs
```

**Issue: CommonJS require() not working**

<strong>Solution:</strong>

```javascript
// Use dynamic import
const { compile } = await import('@bloqr/compiler');

// Or convert to ES modules
```

### Browser issues

**Issue: Module not found**

<strong>Solution:</strong>
Use a bundler (esbuild, webpack):

```bash
npm install -D esbuild
npx esbuild src/main.ts --bundle --outfile=dist/bundle.js
```

**Issue: CORS with local files**

<strong>Solution:</strong>
Run a local server:

```bash
# Python
python -m http.server 8000

# Deno
deno run --allow-net --allow-read https://deno.land/std/http/file_server.ts

# Node
npx serve .
```
